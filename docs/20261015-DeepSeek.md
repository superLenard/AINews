# DeepSeek 再度宕机近 5 小时：对话、API 全线中断，官方全额返还 7 天消耗

## 一、导语

10 月 15 日上午，DeepSeek 网页端、App 及部分 API 服务大面积宕机，持续近 5 小时。用户发消息后只看到一行灰色小字"服务器暂时不可用"，刷新、换网络均无济于事，"DeepSeek 崩了"随即冲上热搜。官方于当天下午发布服务恢复及补偿通知，按账号 7 日内消耗金额以赠金形式**全额返还**。

## 二、事件时间线（北京时间 10 月 15 日）

| 时间 | 进展 |
| --- | --- |
| 08:11 | 故障开始，对话服务、DeepSeek V4 Pro API、DeepSeek V4.1 Flash API 等受影响，官方状态页标记"已定位原因，正在实施修复" |
| 08:36 | 海外监测账号 Status Is Down 报告异常；第三方平台 StatusGator 24 小时内收到 86 条报障 |
| 09:45 | 媒体实测，App 与网页端仍不可用 |
| 13:00 左右 | 记者手动测试，功能已修复、可正常使用 |
| 13:04 | 服务恢复（官方补偿通知确认故障时段为 8:11–13:04） |

**影响范围**：对话服务（Chat Service）、DeepSeek V4 Pro API、DeepSeek V4.1 Flash API 为主，第三方监测还确认涉及上传文件服务、搜索服务等组件。故障期间，用户端出现"服务器暂时不可用""服务器繁忙""消息过于频繁，请稍后再试"等多种提示，卢森堡、波兰、纽约等地用户均有反馈。

## 三、官方回应与补偿方案

DeepSeek 开放平台当天下午发布《服务恢复及补偿通知》：

- 致歉并说明已启动针对服务稳定性的**全面排查和彻底整改**，"全面梳理并剥离单点依赖，坚决杜绝同类问题再次发生"；
- **补偿**：按账号 7 日内（10.8–10.14）的消耗金额，以**赠金形式全额返还**，赠金自动到账，API 计费扣款优先从赠金账户扣除。

关于故障的**具体原因，官方未作说明**。

## 四、这不是今年第一次

据微博智搜统计，进入 2026 年，DeepSeek 已至少发生 **18 次大面积异常**，其中 3 月曾出现近 12 小时的长时间瘫痪，5 月、9 月、10 月也均有服务异常记录（官方状态页事件日历亦显示 2 日、8 日、12 日、15 日多次标红）。

值得注意的背景是，DeepSeek 7 月起引入**峰谷定价**机制，高峰时段 API 价格为空闲时段的 2 倍，希望用价格杠杆调配资源、缓解高峰压力。但从本次结果看，这一杠杆并未挡住新一次宕机。

## 五、原因：官方未明，业内称"多方面可能"

关于此次宕机原因，**官方没有披露**。多家大型云服务与信息基础设施从业者向媒体给出的猜测包括：

- 硬件问题或升级引发的故障；
- 推理服务本身或服务链路上某一环节出问题；
- 流量冲击——据 OpenRouter 数据，10 月当周及整个 10 月，DeepSeek V4.1 Flash 都是**全球调用量最高的模型**，即使宕机当天调用量下滑 11%，仍稳居第一。

以上均为相关人士推测，尚未经官方证实。

## 六、行业观察：调价与开源"撞车"

本次宕机恰逢两个行业节点，被市场解读为"压力不小"：

- 宕机**前一天**，DeepSeek 的 API 价格刚刚上调；
- 宕机**当天**，阶跃星辰正式开源旗舰基座模型 **Step 5 Preview** 完整权重（在 OpenRouter 榜单位居第二），权重同步上线 Hugging Face 与 ModelScope。在竞争对手开源放量的节点上，DeepSeek 服务器再次"繁忙"。

此外，故障期间有海外网友在 Reddit 上直接把宕机与"新模型要来"联系起来，猜测是否为 **DeepSeek-V5** 发布前的大规模变动。此说法仅为社区猜测，无官方佐证。

## 七、结语

作为当下全球调用量最高的 AI 模型之一，DeepSeek 的服务稳定性已成为影响众多开发者与用户工作流的关键因素。近 5 小时的宕机叠加"全额返还"补偿，一方面体现其重视用户信任的姿态，另一方面也再次把"大模型服务的高可用性"这个命题摆上台面——在模型能力竞速之外，稳定与容灾正成为新的竞争维度。
